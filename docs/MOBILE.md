# ใช้บนมือถือ (Android) — คู่มือฉบับสมบูรณ์

แอปมือถือของ "อ่านไทย" เป็น **เว็บแอปที่ติดตั้งลงหน้าจอโฮมได้ (PWA)** ทำงานบน Chrome for Android
และใช้ **Share Sheet** ของระบบเป็นทางเข้า — คืออ่านอะไรอยู่ก็ได้ เลือกข้อความ กดแชร์ เลือก "อ่านไทย" แล้วได้คำแปลทันที

> ทำไมไม่ทำเป็นส่วนขยายบนมือถือ: **Chrome for Android ไม่รองรับส่วนขยายเลย** (ไม่ใช่ข้อจำกัดของโปรแกรมนี้)
> ทางที่ได้ผลจริงและใช้ได้กับทุกแอปคือ PWA + Share Sheet ซึ่งเป็นสิ่งที่ทำไว้นี้

---

## 1. ติดตั้ง (3 นาที)

แอปเป็นไฟล์นิ่งทั้งหมด ไม่มีเซิร์ฟเวอร์หลังบ้าน จึงวางบนโฮสต์ฟรีที่มี HTTPS ได้เลย
เลือกวิธีใดวิธีหนึ่ง:

### วิธี A — GitHub Pages อัตโนมัติ (แนะนำ ถ้าโค้ดอยู่ใน GitHub แล้ว)

โปรเจกต์นี้เตรียม workflow ไว้ให้แล้วที่ `.github/workflows/pages.yml`
ซึ่งจะ **ประกอบเว็บแอปจากต้นฉบับใหม่ทุกครั้งที่ push แล้วเผยแพร่ขึ้น GitHub Pages ให้เอง**

1. เปิด repo บน GitHub → **Settings → Pages**
2. หัวข้อ **Build and deployment → Source** เลือก **GitHub Actions** แล้วกด Save
3. ไปที่แท็บ **Actions** → เลือก workflow "Deploy mobile app (PWA) to GitHub Pages" → **Run workflow**
   (หรือ push โค้ดใหม่ก็จะทำงานเอง)
4. รอประมาณ 1 นาที จะได้ URL `https://ohojames.github.io/ai-translate/`

ข้อดี: อัปเดตแอปได้ตลอดด้วยการ push โค้ด ไม่ต้องอัปโหลดไฟล์เอง และเว็บที่เผยแพร่ตรงกับโค้ดต้นฉบับเสมอ

> ทางเลือกแบบไม่ใช้ Actions: **Settings → Pages → Deploy from a branch → `main` / `/web`**
> (ใช้ได้ทันทีเพราะโฟลเดอร์ `web/` ถูก commit ไว้แล้ว แต่ต้องรัน `npm run build:web` เองก่อน push ทุกครั้ง)

### วิธี B — Netlify Drop (ไม่ต้องมี repo ก็ได้)

1. แตกไฟล์ `dist/atthai-web-<เวอร์ชัน>.zip` ออกมา (จะได้โฟลเดอร์ที่มี `index.html` อยู่ข้างใน)
2. เปิด **https://app.netlify.com/drop**
3. ลาก **โฟลเดอร์นั้น** ทั้งโฟลเดอร์ไปวางในหน้าเว็บ
4. รอสักครู่ จะได้ URL แบบ `https://xxxx-yyyy.netlify.app` — ใช้อันนี้ได้เลย
   (ถ้าอยากเก็บไว้ถาวรให้สมัครฟรีแล้วกด "Claim site")

### วิธี C — GitHub Pages แบบแยก repo (ถ้าไม่อยากใช้ Actions)

1. สร้าง repo ใหม่ (Public) เช่น `atthai`
2. กด **uploading an existing file** แล้วลาก **ไฟล์และโฟลเดอร์ทั้งหมดที่อยู่ข้างใน** โฟลเดอร์ `web/`
   (ต้องเห็น `index.html`, `sw.js`, `manifest.webmanifest` อยู่ที่ระดับบนสุด) → Commit
3. ไปที่ **Settings → Pages** → Source: *Deploy from a branch* → Branch: `main` / `(root)` → Save
4. รอประมาณ 1 นาที จะได้ URL `https://<ชื่อผู้ใช้>.github.io/atthai/`

สำหรับคนที่ใช้คำสั่ง `git`/`gh` สะดวกกว่า:

```bash
cd web
git init && git add -A && git commit -m "atthai web"
gh repo create atthai --public --source=. --push
gh api -X POST repos/:owner/atthai/pages -f 'source[branch]=main' -f 'source[path]=/'
```

### วิธี D — Cloudflare Pages

สร้างโปรเจกต์แบบ *Direct Upload* แล้วลากโฟลเดอร์ `web/` ขึ้นไป ได้ HTTPS ฟรีเช่นกัน

> **ต้องเป็น HTTPS** (หรือ `http://localhost`) เท่านั้น เพราะ Service Worker และ Share Sheet ถูกจำกัดไว้ที่ secure context
> ถ้าอยากลองในวง LAN เฉย ๆ ให้เปิด `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
> แล้วใส่ `http://<ไอพีเครื่องคอม>:8080` จากนั้นรีสตาร์ท Chrome (ใช้สำหรับทดสอบเท่านั้น)

### ติดตั้งลงหน้าจอโฮม

1. เปิด URL ข้างบนด้วย **Chrome for Android**
2. กดเมนู ⋮ → **ติดตั้งแอป** (หรือ *เพิ่มลงในหน้าจอหลัก*)
3. เปิดแอปจากไอคอนที่หน้าจอโฮมได้เลย และจะเห็น "อ่านไทย" ในเมนูแชร์ของทุกแอป

## 2. วิธีใช้

### ทางที่ 1 — แชร์จากแอปอื่น (ทางหลัก)

```
อ่านหนังสือ/เว็บ/อีเมลอยู่  →  เลือกข้อความ  →  กด แชร์  →  เลือก "อ่านไทย"
        ↓
แอปเปิดขึ้นพร้อมคำแปลทันที (ไม่ต้องสลับแอปไปมา ไม่ต้องคัดลอกวาง)
        ↓
กด "บันทึกเข้าคลังคำ" เพื่อกลับมาทบทวนภายหลัง
```

ใช้ได้กับ **ทุกแอปที่แชร์ข้อความได้** เช่น Chrome, Google Drive (PDF), Kindle, Gmail, Google Docs, แอปอ่าน PDF ต่าง ๆ

### ทางที่ 2 — วางจากคลิปบอร์ด

เปิดแอป → กด **📋 วางจากคลิปบอร์ด** (Android จะขออนุญาตอ่านคลิปบอร์ดครั้งแรก)
หรือกดค้างในช่องข้อความแล้วเลือก **วาง** — ระบบจะแปลให้อัตโนมัติทันทีที่วาง

### ทางที่ 3 — อ่าน PDF ในแอป

กดเมนู **📄 PDF** → **เปิดไฟล์** → เลือกไฟล์ PDF จากเครื่อง
แล้ว **แตะค้างเพื่อเลือกคำ** → กดปุ่ม **🌐 แปล** ที่ลอยขึ้นมา (หรือแตะปุ่ม "แปลหน้านี้" เพื่อแปลทั้งหน้า)

### อ่านคำในประโยคที่แชร์มา

ถ้าแชร์มาทั้งประโยค แอปจะเสนอ **"คำในข้อความนี้"** เป็นปุ่มให้แตะ
แตะคำใดก็ได้เพื่อดูคำพ้อง ตัวอย่างประโยค และตัวช่วยจำของคำนั้น

### ทางที่ 4 — คลังคำและทบทวน

เมนู **📚 คลังคำ** (ค้นหา กรอง แก้โน้ต/แท็ก ปักดาว ส่งออก/นำเข้า) และ **🎯 ทบทวน** (บัตรคำ + ให้คะแนน 4 ระดับ)

ต่างกันเฉพาะสิ่งที่ตัวเบราว์เซอร์ทำได้:

| ความสามารถ | ส่วนขยาย (คอม) | แอปมือถือ |
| --- | --- | --- |
| ดับเบิลคลิกคำบนหน้าเว็บเพื่อแปล | ✅ | ❌ ใช้วิธีเลือกข้อความ → แชร์ แทน |
| คลุมข้อความแล้วมีปุ่มลอย | ✅ | ❌ (แตะค้างเลือกคำในตัวอ่าน PDF ได้) |
| เปิดลิงก์ PDF แล้วเข้าตัวอ่านอัตโนมัติ | ✅ | ❌ (เปิดไฟล์จากในแอปแทน) |
| แชร์ข้อความจาก **ทุกแอป** เข้ามาแปล | ❌ | ✅ |
| อ่าน PDF ในแอป + แตะคำเพื่อแปล | ✅ | ✅ |
| แปลทั้งหน้า PDF | ✅ | ✅ |
| Google / Google Dictionary / MyMemory | ✅ | ✅ |
| Datamuse / Tatoeba / Wiktionary (คำพ้อง ตัวอย่าง ความหมาย) | ✅ | ✅ |
| AI: OpenAI / OpenRouter / Gemini / Claude | ✅ | ✅ |

| ซิงก์กับผู้ให้บริการอื่น | – | ❌ (ไม่มีเซิร์ฟเวอร์กลาง ตามหลักความเป็นส่วนตัว) |

## 4. รวมคลังคำระหว่างคอมกับมือถือ

สองแอปอยู่คนละโดเมน ฐานข้อมูลจึงแยกกัน (เจตนา: ไม่มีเซิร์ฟเวอร์กลาง ข้อมูลอยู่กับคุณ)
วิธีรวมคลัง:

1. ฝั่งที่มีคำอยู่ → **ตั้งค่า → ข้อมูล & สำรอง → ส่งออก JSON**
2. ส่งไฟล์ให้อีกเครื่อง (Google Drive / LINE / อีเมล)
3. อีกเครื่อง → **ตั้งค่า → ข้อมูล & สำรอง → นำเข้า JSON** → ระบบจะ **รวม** คำซ้ำให้อัตโนมัติ (ไม่ทับของเดิม)

คำที่ซ้ำจะถูกรวมข้อมูล (คำแปล/คำพ้อง/ตัวอย่าง/โน้ต) เข้าด้วยกัน และคงกำหนดวันทบทวนเดิมไว้

## 5. ตั้งค่า AI บนมือถือ

**ตั้งค่า → AI ช่วยอธิบาย** แล้วเลือกเจ้า (ค่าใช้จ่ายต่อคำถูกมาก เพราะส่งข้อความสั้น)

| เจ้า | ค่าที่ต้องใส่ |
| --- | --- |
| OpenAI | provider `openai`, model `gpt-4o-mini`, ใส่ API key |
| OpenRouter | provider `openai`, baseUrl `https://openrouter.ai/api/v1`, model เช่น `google/gemini-2.0-flash-001` |
| Google Gemini | provider `gemini`, model `gemini-2.0-flash`, ใส่ API key (มีโควตาฟรี) |
| Anthropic Claude | provider `anthropic`, model `claude-3-5-haiku-latest`, ใส่ API key |

กด **ทดสอบการเชื่อมต่อ AI** เพื่อยืนยัน แล้วเปิดสวิตช์ "เปิดใช้ AI ช่วยอธิบาย"
จากนั้นในหน้าหลักจะมีปุ่มเลือก **"AI อธิบายละเอียด"** ให้สลับได้

> คำเตือนด้านความปลอดภัย: API key ถูกเก็บไว้ในเครื่องของคุณเท่านั้น (IndexedDB) แต่การเรียก API จากเบราว์เซอร์
> ทำให้คีย์อยู่ในหน้าที่โหลดได้ — เหมาะกับการใช้ส่วนตัวบนเครื่องตัวเอง ถ้าใช้เครื่องที่คนอื่นใช้ร่วมกันควรล็อกหน้าจอ

## 6. แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
| --- | --- |
| เมนูแชร์ไม่เห็น "อ่านไทย" | ต้อง **ติดตั้งแอปก่อน** (ไม่ใช่แค่เปิดในแท็บ) และเปิดแอปหนึ่งครั้งหลังติดตั้งเพื่อให้ service worker ลงทะเบียน |
| กด "วางจากคลิปบอร์ด" แล้วขึ้นว่าอ่านไม่ได้ | Android บังคับให้ต้องมาจากการแตะของผู้ใช้ — ลองกดปุ่มอีกครั้ง หรือกดค้างในช่องข้อความแล้วเลือก "วาง" (ระบบจะแปลให้เอง) |
| แชร์แล้วเปิดแอปแต่ไม่มีข้อความ | ปิดแอปแล้วแชร์ใหม่ · เช็คว่าแชร์ *ข้อความ* ไม่ใช่ *ลิงก์* เปล่า ๆ |
| คำแปลครั้งแรกช้า | การเรียกผู้ให้บริการฟรีครั้งแรกอาจใช้ 2-5 วินาที หลังจากนั้นจะเร็วเพราะมีแคช |
| ไม่ได้ตัวอย่างประโยค | เปิด AI (ได้ตัวอย่างแบบเหตุการณ์จริง 2-4 ประโยค) หรือเปิด Tatoeba ในหน้าตั้งค่า |
| เปิดแอปแล้วเห็นหน้าเก่า | ปิดแอปทั้งแอป (ปัดจาก recents) แล้วเปิดใหม่ — service worker จะอัปเดตเองในรอบถัดไป |
| อยากย้ายไปโดเมนใหม่ | อัปโหลดใหม่แล้วติดตั้งทับได้เลย คลังคำยังอยู่ที่เดิมถ้าใช้โดเมนเดิม |
| คลังคำหายหลังล้างข้อมูลเบราว์เซอร์ | ข้อมูลอยู่ใน IndexedDB ของเบราว์เซอร์ — ควร **ส่งออก JSON เก็บไว้** เป็นระยะ |

## 7. สำหรับนักพัฒนา

```bash
npm run build:web     # ประกอบ web/ จากต้นฉบับใน extension/src (ต้องรันก่อนเสมอหลังแก้โค้ด)
npm run serve:web     # เปิดเซิร์ฟเวอร์ทดสอบที่ http://localhost:8080 (secure context จึงทดสอบ PWA ได้ครบ)
npm run e2e:web       # ทดสอบอัตโนมัติ 43 รายการบน Chromium โหมดมือถือ
npm run verify        # ตรวจทั้งหมด: ส่วนขยาย + เว็บแอป
npm run package       # แพ็ก ZIP ทั้งส่วนขยายและเว็บแอป (ไว้ที่ dist/)
```

### หลักการสำคัญ: ต้นฉบับเดียว สองแอป

โค้ดการแปลและหน้าจอทั้งหมดอยู่ใน `extension/src/**` ที่เดียว
`npm run build:web` จะคัดลอกมาที่ `web/src/**` แล้วสร้างไฟล์ที่เว็บต้องมีเอง (config, ไอคอน, รายการแคช)
ถ้าลืมรัน build ระบบตรวจสอบ (`npm run check`) จะฟ้องว่าไฟล์ค้างเก่า

ไฟล์ที่เป็นของเว็บเอง (ไม่ถูกทับ):

```
web/index.html            หน้าหลัก (วาง/แชร์/แตะคำ)
web/sw.js                 service worker: แคชเปลือกแอป + รับ share target
web/manifest.webmanifest  PWA manifest (มี share_target)
web/src/config.js         ที่อยู่ไฟล์ pdf.js + เวอร์ชัน (สร้างโดย build)
web/src/app/              หน้าหลัก + สไตล์ของมือถือ
```

จุดเชื่อมสภาพแวดล้อมอยู่ที่ `extension/src/common/platform.js` ที่เดียว
(`extension` = ส่วนขยาย, `web` = PWA, `headless` = ทดสอบใน Node) — โมดูลอื่นไม่ต้องรู้ว่ากำลังรันที่ไหน

### ทำไมต้องใช้ endpoint ที่มี CORS

หน้าเว็บธรรมดาเรียก API ข้ามโดเมนได้เฉพาะที่อนุญาต ตรวจสอบได้ด้วย `npm run cors` ผลที่ได้:

| บริการ | ใช้บนเว็บได้ | หมายเหตุ |
| --- | --- | --- |
| Google Translate (`translate.googleapis.com`) | ✅ | `Access-Control-Allow-Origin: *` |
| Google Dictionary (`clients5`) | ✅ | ACAO `*` |
| MyMemory | ✅ | ACAO `*` |
| Datamuse | ✅ | ส่ง ACAO กลับตาม origin |
| Tatoeba (api.tatoeba.org) | ✅ | API ใหม่มี CORS และให้คำแปลไทยมาด้วย |
| Wiktionary REST | ✅ | ACAO `*` |
| OpenAI / OpenRouter / Gemini / Anthropic | ✅ | Anthropic ต้องส่ง header `anthropic-dangerous-direct-browser-access` |
| LibreTranslate | ✅ | ต้องเป็นเซิร์ฟเวอร์ที่เปิด CORS |
| DeepL | ❌ | ไม่มี CORS — ใช้ได้เฉพาะในส่วนขยาย |
